# パフォーマンス予算(WASD探索型サイト)

## 目標値

| 指標 | 目標 | 理由 |
|---|---|---|
| 初回読み込み(3G相当でなく通常回線) | 8秒以内 | 離脱防止 |
| フレームレート(デスクトップ) | 60fps | WASD移動の快適さ |
| フレームレート(ミドルスペックノート) | 30fps以上 | 最低保証 |
| ドローコール | 150以下 | WebGL負荷 |
| メモリ(タブ全体) | 1.5GB以下 | ブラウザ安定性 |

## データサイズの予算(本リポジトリの実測に基づく)

| アセット | 実測/目安 | 予算内の使い方 |
|---|---|---|
| 形状モデル 49k面(SPC) | 約1.4MB(OBJ) | 既定表示に使用 |
| 形状モデル 200k面(SPC) | 約6.9MB(OBJ) | 高品質モードのみ |
| 生成LOD(5k/15k面) | 約0.2-0.5MB | 遠景・低スペック端末 |
| 生成コリジョン(15k面) | 約0.5MB | 当たり判定専用(非表示) |
| 生成標高マップ 2048px | 約2.5MB | WASD移動の地形追従 |
| 生成タイル(z0-z3, 5種×85枚) | 約17MB | ズーム時に段階読み込み |
| 全球ベースマップJPG(直接) | 約1-3MB/枚 | タイル未使用時の代替 |
| ONCギャラリー783枚 | 合計大 | 全読み込み禁止。表示時に遅延読み込み |
| MASCOT FITSデータ | 大 | サイト側でJPG/PNGへ事前変換 |
| SPICEカーネル | 大 | ブラウザに直接読ませない。事前計算したJSONへ |

## 読み込み戦略

1. **初回**: LOD3メッシュ(0.2MB) + z0タイル(1枚) + poi_master.json → すぐに操作可能に
2. **操作開始後**: 49k面モデル + z1-z2タイル + 標高マップを段階読み込み
3. **高品質モード選択時のみ**: 200k面 + z3タイル
4. **画像・試料**: POIに近づいた時・クリック時に初めて読み込み(遅延ロード)
5. **MASCOT FITS**: ビルド時にJPGへ変換したものを配置(変換スクリプトは `conversion/README.md` 参照)

## 計測方法

- Lighthouse(CIに組み込み): Performance 80以上
- Chrome DevTools Performance パネルでフレーム落ちを計測
- WebGL: `renderer.info.render.calls` でドローコール数を確認
